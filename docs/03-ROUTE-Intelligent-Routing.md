# Layer 3 — ROUTE：Cost-Intelligent Routing（成本智慧路由）

> 對的任務，用對的模型。
> 效果目標：**人工成本 -60%**（不再每件事都用最貴的腦）

---

## 為什麼需要這一層

「反正都問最強的模型就好」——這是最貴、最慢、也最懶的策略。

- 已知任務（有 VAC）用旗艦模型 → 花 10 倍的錢做例行事
- 未知任務用便宜模型 → 省小錢、繞遠路、最後還是要重來
- 沒有路由規則 → 成本無法預測，也無法對老闆交代

ROUTE 的主張：**依「任務是否已知」把工作分流到不同成本層級。**

---

## 核心觀念

| 任務狀態 | 用什麼 | 單次成本（示意） | 目的 |
|----------|--------|------------------|------|
| **未知**：沒有 VAC，方法待探索 | 高階推理（Opus / GPT-4 級） | ¥50 | 探索、找出方法、產出 VAC |
| **已知**：有 VAC，只是換內容 | 低成本執行（Haiku / mini 級） | ¥5 | 照規格執行 |
| **可完全重複**：VAC 穩定、步驟固定 | Agent 自動化 | ¥0.5 | 排程 / 觸發即跑 |

> 幣別與數字只是相對示意，重點是**三個數量級的差距**。

---

## 決策樹

```
任務進來
   │
   ├─ 我們的 VAC 庫裡有對應規格嗎？
   │     ├─ 有，且步驟已固定、跑過多次 ──▶ Agent 自動化（¥0.5）
   │     ├─ 有，但這次內容不同        ──▶ 低成本模型 + VAC（¥5）
   │     └─ 沒有                      ──▶ 高階模型探索（¥50）
   │
   └─ 探索完成、方法確定 ──▶ 產出 VAC，存入庫 ──▶ 下次此任務變「已知」
```

**關鍵**：每一次「未知 → 已知」的轉換，都要留下 VAC，否則下次又是 ¥50。

---

## 具體做法

1. **分類當前任務**：對照 VAC 庫，判定 未知 / 已知 / 可重複。

2. **查 RULES 的成本上限**：VAC 的 `④ RULES` 若有預算天花板，路由不能超過。

3. **選層級並寫進 VAC 的 `⑥ TOOLS`**：
   - 未知 → `Opus（探索、產 VAC）`
   - 已知 → `Haiku（照 VAC 執行）`
   - 可重複 → `Agent（排程 / webhook 觸發）`

4. **設升級與降級條件**：
   - 升級：低成本模型連續兩次無法通過 ACCEPTANCE → 暫時升到高階模型重探。
   - 降級：高階模型探索完成、方法穩定 → 下次固定用低成本層級。

5. **記錄實際成本與次數**：回填 VAC metadata 的「Last run」，作為 LEARN 的輸入。

|------|------|
| 路由決策 | 寫入 VAC 的 `⑥ TOOLS`：層級 + 觸發方式 |

## 反模式 Anti-patterns

- ❌ **一律旗艦**：例行任務燒探索預算。
- ❌ **一律最便宜**：未知問題硬要便宜模型硬解，繞遠路。
- ❌ **探索完不留 VAC**：下次同一題又付 ¥50。
- ❌ **沒有升級閥值**：便宜模型卡住還在原地重試，時間成本爆表。
- ❌ **路由憑感覺**：沒有「是否已知」這個客觀判準。

---

## 檢查清單

- [ ] 已對照 VAC 庫，判定任務為 未知 / 已知 / 可重複
- [ ] 選定的模型層級已寫入 VAC 的 `⑥ TOOLS`
- [ ] 不違反 `④ RULES` 的成本上限
- [ ] 定義了升級條件（何時往上）與降級條件（何時往下）
- [ ] 若判定「未知」，已規劃探索完成後要產出 VAC
- [ ] 本次成本與執行次數會被記錄

---

## 範例

**任務**：幫這個月 5 篇部落格各配一張封面說明圖。

- VAC 庫檢查：有 `VAC-072-v1.3-blog-cover`，跑過 20 次，步驟固定。
- 判定：**可完全重複**。
- 路由：Agent 自動化，¥0.5 / 張，接在 CMS 發文的 webhook 上。
- 升級條件：連續 2 張未通過 Visual 驗收 → 轉 Haiku 人工帶跑一次並更新 VAC。

**對照**：若是「第一次要做一種全新風格的封面」→ 判定未知 → Opus 探索 → 產出 `v1.0` 存庫。
